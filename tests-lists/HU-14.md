# Lista de Pruebas - HU-14: Ubicación con Google Maps (Derivada de HU-03 y HU-04)

## Criterios de Aceptación
1. [x] El formulario tiene la opción de marcar la ubicación usando Google Maps (dirección, coordenadas, enlace de Google Maps o "Usar mi ubicación actual", con vista previa del mapa).
2. [x] La ubicación es opcional.
3. [x] El detalle de la publicación muestra el mapa con el marcador (depende de HU-12).
4. [x] Si no se indicó ubicación, no se muestra el mapa.

## Casos de Prueba (Model: mapa.js)

### Caso 1: Sin ubicación
- [x] Si la ubicación está vacía, solo tiene espacios, no se envía o es null -> no hay mapa ('').

### Caso 2: Dirección o coordenadas escritas
- [x] Una dirección genera la URL del mapa embebido con el texto codificado (sin espacios en los extremos).
- [x] Unas coordenadas generan la URL del mapa embebido con el marcador en esas coordenadas.

### Caso 3: Enlace de Google Maps
- [x] Si el enlace tiene parámetro `query` o `q`, el marcador usa ese valor.
- [x] Si el enlace tiene `@lat,lng` en la ruta, el marcador usa esas coordenadas.
- [x] Si el enlace es `/maps/place/<lugar>`, el marcador usa el nombre del lugar.
- [x] Si es un enlace corto (maps.app.goo.gl) que no indica el lugar -> no hay mapa embebido (se mantiene el enlace).

### Caso 4: Ubicación no admitida
- [x] Esquema `javascript:` o enlace ajeno a Google Maps -> no hay mapa.

### Caso 5: Coordenadas del dispositivo
- [x] Latitud y longitud se formatean con 6 decimales como `lat,lng`.
- [x] Si no son números válidos -> ''.

## Casos de Prueba (Presenter: detallePresenter.js)
- [x] Si el detalle tiene mapa embebido, se muestra el iframe del mapa con su URL escapada.
- [x] Si no se indicó ubicación, no se muestra el mapa.
- [x] Al renderizar una publicación con ubicación guardada, se genera el mapa.
- [x] Al renderizar una publicación sin ubicación, no se genera el mapa.
